Explanations

Internal vs external fragmentation

Internal fragmentation is wasted space inside an allocated block. It appears when memory is handed out in fixed units (blocks, pages, buddy sizes) bigger than the request. Example: 70 KB with 64 KB blocks gets 128 KB, so 58 KB is wasted. The process owns that space, so nobody else can use it. It is drawn hatched.

External fragmentation is wasted space between allocated blocks. There is enough free memory in total, but it is split into small holes that are not next to each other, so a large request fits nowhere. It comes from variable-size contiguous allocation as processes come and go.

Metric used here: ext. frag = 1 − largest hole ÷ total free
0% means all free memory is one hole. Near 100% means it is scattered in tiny holes.

50-percent rule (Knuth): with first fit, for every N allocated blocks about 0.5 N blocks are lost to fragmentation, so up to a third of memory can be unusable.

First Fit

Scan the holes from the start of memory and take the first one big enough. The rest of that hole stays free.

Fast because it stops early. Small leftover holes tend to pile up near the start of memory.

Best Fit

Check every hole and take the smallest one that is big enough, which gives the smallest leftover.

Saves large holes for large requests, but leaves tiny slivers that are too small to use. It has to search the whole list unless the list is sorted by size.

Worst Fit

Take the largest hole. The idea is that the leftover stays big enough to be useful.

In practice it quickly breaks up the big holes that large processes need, so it usually does worst in simulations.

Next Fit

Like First Fit, but the search starts where the last allocation ended (the ▼ pointer) and wraps around to the start.

This spreads allocations across memory and avoids rescanning the crowded start. It often fragments the large hole at the end more than First Fit does.

Coalescing

When a process is freed, its hole is merged with any free neighbour (left and right) into one bigger hole. This is cheap because only the neighbours are checked.

Without it, memory fills with holes that sit side by side but count as separate. A request can then fail even though the free space is contiguous. Untick the option to see this. Coalescing cannot join holes that have an allocated block between them; that needs compaction.

Compaction

Move (relocate) every allocated block to one end of memory so that all free space becomes one big hole. This removes external fragmentation completely.

Cost: every moved byte has to be copied and the moved processes are paused. The simulator reports the KB moved. It only works with dynamic relocation (execution-time binding, for example a base/relocation register), because the process's addresses change.

Fixed block size mode

Every request is rounded up to a multiple of the block size. Holes are always whole blocks, so there are no tiny slivers. The trade-off is internal fragmentation in the last block of each process.

Paging is the same idea taken further: a process doesn't have to be contiguous, so external fragmentation disappears and only internal fragmentation in the last page remains.

Buddy system

Memory size is a power of 2, and each request is rounded up to the next power of 2. If no free block of that size exists, a larger block is split in half again and again. The two halves are "buddies".

When a block is freed, it merges with its buddy if the buddy is free too, and this repeats upward. The buddy of a block at address A with size S is at A XOR S.

Splitting and merging are fast (Linux uses this for physical pages). The drawback is internal fragmentation of up to about 50%: 129 KB needs a 256 KB block. Two free neighbours that are not buddies cannot merge.
